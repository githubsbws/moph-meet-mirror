Key Architectural Differences

Storage & Persistence

  • core: PostgreSQL via Sequelize ORM. Full relational schema: User, RoleMap, Meet, MeetInvite, Patient, MedRecord, IOTRecord. Data persists indefinitely.
  • core-lite: In-memory NodeCache for session tokens (lost on restart) + SQLite (better-sqlite3) for rooms (24h TTL, survives restart). No relational schema.

Authentication Model

  • core: apiKeyAuth() for appointment endpoints reads API key from x-api-key header or env config.
  • core-lite: auth() middleware handles both session tokens AND the static API key whitelist in a single middleware. API key passed as Authorization: Bearer <key>.

Meet URL Format

  • core /api/meet/reserved: returns a direct Jitsi URL with embedded HS256 JWT. Anyone with the URL can join.
  • core-lite /api/meet/reserved: returns /exam/:id (doctor) + /queue/:id?jwt=… (patient). Doctor must authenticate via ProviderID — room is locked to their CID.

Removed Capabilities (not in scope for moph-meet)

  • Username/password login (/api/auth)
  • User search (/api/user/:keyword)
  • Patient records: IOT realtime, IOT history, Medical records (/api/patient/*)
  • External AI medical record notification (hardcoded to 45.154.24.212:3501)
