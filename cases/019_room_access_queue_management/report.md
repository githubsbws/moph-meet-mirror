# รายงานการพัฒนาระบบห้องตรวจและห้องประชุม

## ขอบเขตที่ทำ

- เพิ่มชื่อห้อง วันเวลา และชนิดสิทธิ์ `Public` / `Restricted` ขณะสร้างห้อง
- เพิ่มทะเบียนบุคลากรภายในแอป แยกตาม H-Code พร้อมค้นหาและเชิญแพทย์/พยาบาล
- รองรับการเชิญข้าม H-Code เฉพาะรายที่เจ้าของห้องระบุ
- ห้องตรวจบังคับใช้เลขบัตรประชาชน 13 หลักที่ผ่าน checksum ก่อนออกลิงก์ผู้ป่วย
- ลิงก์ผู้ป่วยเป็นลิงก์เฉพาะคำเชิญ เก็บ CID ในรูป hash และยกเลิกคิวหรือทำเครื่องหมาย No Show ได้
- เพิ่ม Waiting Room สำหรับห้องประชุม Public: ผู้สร้างออกลิงก์เชิญ, อนุมัติหรือปฏิเสธผู้เข้าร่วมได้
- ส่งข้อความแจ้งเตือนไป LINE OA ที่ตั้งค่าไว้เมื่อสร้างห้องประชุม โดยไม่ส่งข้อมูลผู้ป่วย
- จำกัด Dashboard และ usage log ตาม H-Code ของผู้ใช้งาน
- ปรับ Web และ Mobile ให้รองรับชื่อห้อง, สิทธิ์ห้อง, และ flow เชิญผู้ป่วยแบบ CID

## ข้อสังเกตด้านการใช้งาน

- `Public` ในระบบนี้ไม่ได้หมายถึงใครก็เข้าห้องวิดีโอได้: ต้องใช้ลิงก์คำเชิญและรอการอนุมัติจากเจ้าของห้อง
- การบังคับสิทธิ์ของ Jitsi ที่ระดับวิดีโอจำเป็นต้องตั้งค่า JWT/lobby บน Jitsi server เพิ่มเติม; ปัจจุบันแอปบังคับสิทธิ์ก่อนส่งผู้ใช้ไปยังห้องแล้ว
- ปฏิทินวันหยุดราชการยังต้องระบุแหล่งข้อมูลราชการและ credential/URL สำหรับการ sync ก่อนเปิดใช้งานจริง เพื่อไม่ให้ใช้ข้อมูลวันหยุดที่คลาดเคลื่อน

## การตรวจสอบ

- ตรวจ syntax ของ Core และ storage adapters ด้วย `node --check`
- ตรวจ TypeScript ของ Mobile ด้วย `npx tsc --noEmit`
- ตรวจ `git diff --check`
- ทดสอบ API ด้วย memory store: การเชิญบุคลากร, CID ไม่ถูกต้องถูกปฏิเสธ, CID ถูกต้องออกคำเชิญได้, No Show ปิดสิทธิ์ลิงก์, และ Waiting Room
- ทดสอบ UI Web ใน browser: login, ฟอร์มสร้างห้อง, ชื่อห้อง, Public/Restricted, ค้นหาบุคลากร และตรวจ console โดยไม่พบ error
